# M714: ledger foundation repairs

The ledger is durable story state. Workers maintain it from the completed
scene, writer facts, historical sources and authorized offscreen developments.
The storyteller receives a selected view. The final auditor corrects factual
contradictions and omissions while preserving valid worker judgments.

This milestone fixes confirmed system defects from the M713 audit. It does
not substitute one story's character names or reset the story to its brief.

## How the whole pipeline now relates

1. Founder establishes the writer's starting world and identities from original
   inputs. Starting relationship values do not erase later earned developments.
2. Scene reads the completed sequence through its ending and records physical
   presence, current pose, clothes, injuries and event-driven standings.
3. World continues due or affected absent lives under existing story authority.
   Quiet people remain where established; silence is not departure.
4. People records stable identity, character interpretation and open obligations.
   Original appearance facts belong in canonical physical locks.
5. Keeper retains folded history. Original pages remain available for retrieval.
6. The assembler selects relevant records and fits the complete storyteller
   request. It does not edit the ledger while rendering a prompt.
7. Auditor is the final factual authority. It reads new material and relevant
   originals, repairs omissions, and keeps its existing source scratchbook and
   stable profile approvals. Changed facts, authority or source marks reopen
   affected reviews. Current scene changes still need current verification.

The order and stale ownership rules remain. M714 introduces no additional model
that judges the housekeeper. Source reference checks establish provenance and
transport integrity, not a rival interpretation of the story.

## Focused milestone evidence

Ran only `node tests/harness/m714-foundation.mjs`. Two unsupported launch flags
failed before any fixture execution; the plain invocation passed. The fixture
uses actual application modules and an in-memory store shim with mocked source
responses. It sends no real provider requests and advances no live story.

The selected view used more than100 stored people, a named absent queen, an
older promise, older MC knowledge and an old explicitly named item. All reached
the complete request. Keeper on and off long-history examples each measured
175445 conservative input tokens, within181000 input room after reserving16000
answer tokens and3000 margin in a200000 context. The current move, latest
exchange and closing writer instruction remained; rendering left its state
unchanged. Context fit metadata survives receipt finalization.

Seven original chunks fit one mocked call. An unchanged reread made zero calls.
A deliberately truncated group was retried smaller and completed in the same
run. The fixture also exercised exact held-profile appendix omission, a single
World knowledge copy, durable canon checkpoint reuse across clock change and
invalidation on changed hair, plus a total worker wait deadline.

No theme suite, broad application suite, long gameplay, provider matrix or
live browser ledger inspection ran. These results verify changed code paths,
not whether a real model will capture every future nuance. Actual source/model
replies remain responsible for factual completeness; green requires the existing
completed authoritative live review with no outstanding findings.

The total foreground job wait is bounded; other existing optional send helpers
and provider latency are not represented as a five-second total-send guarantee.
Token counts are conservative estimates, not exact provider tokenizer results.
Large immutable instructions or a huge current input can still require a larger
connection context. Missing historical facts can require recovery once; ordinary
later scenes reuse unchanged source receipts rather than rescan everything.
